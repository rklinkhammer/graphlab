## Explicit unresolved backend/workload gaps

- The first instrumented workload now reports application message/payload rates, errors, rejection/backpressure counters and local echo-service mean/p95 histogram bounds. The subsequent application-edge increment adds multiple declared edge streams and fixture-defined reconnect counts. Increment E adds opt-in GLM1 message/trace IDs and exact retained-capture correlation; delivered-loss measurements and end-to-end/one-way network latency remain unsupported. Other workloads must opt into the documented contract; interface counters cannot supply missing application measurements.
- Finalized packet history and bounded catalog recycling/rebuild/recovery are implemented below. Active/unmanifested files, arbitrary imported PCAP formats, payload inspection/reassembly, packet direction attribution remain unsupported. Separate opt-in GLM1 correlation is implemented in increment E. Late or older segments below the durable retirement boundary require explicit rebuild; repeated database recovery requires administrator archival of the preserved quarantine.
- [Application dataflow mapping v1](application-dataflow.md) now declares directed workload edges and explicit network-resource associations, with connected console views. Endpoint-owned per-edge metrics are implemented in increment A below. Observed paths and multiple components per workload remain unsupported. Increment E fixture streams do not automatically map to application edges.
- Source-specific pause/resume is implemented for opt-in Docker workloads (increment B below). QEMU and legacy workloads advertise no source control. Run quiesce retains whole-run semantics.
- [Durable process-log snapshots v1](process-logs.md) retain collected Docker, QEMU worker and available container-runner output after destruction. Collection remains a discontinuous bounded tail: runtime rotation and output between polls can omit bytes. Guest serial and QEMU stderr files are separate sources, not silently merged. See increment C evidence and limits below.
- Serial coverage remains from attachment. Guest images must supply any login service. Real Linux Docker/QEMU/OVS validation is separate from mocked browser and portable tests.

## Packet-index maintenance and recovery — 23 September 2026

The catalog now retains 1,000 recent keyed receipts and advances a durable retirement boundary when evicting older entries. The receipt, packet rows and boundary update commit atomically. Scanning an evicted artifact cannot automatically replay its packets after restart. Candidate selection retains the newest 1,000 segments per run; automatic scans admit at most 128 new segments per request. Legacy receipts migrate when their registered manifests are read, with a bounded allowance of up to 1,000 pinned legacy entries rather than dropping old deduplication state.

This boundary is explicitly a lossy admission rule: old/late manifests, clock regressions and ties ordered below it may be excluded even if never indexed. The API/console expose the boundary, catalog evictions and candidate truncation. A run-level rebuild explicitly bypasses retirement for a bounded replay, replaces that run's derived rows and invalidates old cursors. Other runs' sources are untouched; global row/byte retention still applies.

Authenticated, Origin/CSRF-protected maintenance routes add `packet-history.rebuild` and `packet-history.recover` RPC operations. Recovery requires every run stopped or destroyed and explicit `scope: all-runs`. It preserves one quarantine set, uses a durable intent to survive interruption, publishes a fresh derived database with a new cursor epoch, and leaves captures/execution/application telemetry unchanged. Repeated independent recovery refuses to overwrite the quarantine. The [contract and operator procedure](packet-history.md#recovery-procedure-and-failure-behavior) describe partial rebuilds, failed recovery and space requirements.

## Increment A traffic-lease remediation — 23 September 2026

Resolved the P1 delayed-TCP-record defect. A shared private I/O helper bounds every connection/read/write wait by the active absolute traffic deadline and the ordinary timeout, rechecking after readiness and before I/O. This preserves unleased development behavior and existing reporting semantics. Bytes already accepted by the kernel are not retroactively withdrawn.
