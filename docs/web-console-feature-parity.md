## Explicit unresolved backend/workload gaps

- The first instrumented workload now reports application message/payload rates, errors, rejection/backpressure counters and local echo-service mean/p95 histogram bounds. Reconnects, message/trace IDs, delivered-loss measurements, exact message-to-capture correlation, multiple streams per node and end-to-end/one-way network latency remain unsupported. Other workloads must opt into the documented contract; interface counters cannot supply missing application measurements.
- Recent packet inspection and bounded packet history require a capture-decoding/index contract with storage limits and observation-point semantics. Existing PCAPNG downloads and operational timeline remain available; they are not packet history.
- Separate application dataflow/network-path views require declared application edges and their mapping to network resources. Current topology shows declared network resources and optional management attachments. No synthetic application graph is added.
- Source-specific pause/resume requires a scoped workload control contract. Run quiesce affects the run and is not represented as source pause.
- Process logs are snapshots of the runtime's bounded tail, not durable Graphlab artifacts. Container logs become unavailable after container removal; retained terminal recordings remain downloadable. QEMU worker journal availability depends on host journald retention; container-runner stderr is not independently exported by this endpoint.
- Serial coverage remains from attachment. Guest images must supply any login service. Real Linux Docker/QEMU/OVS validation is separate from mocked browser and portable tests.

## Application telemetry increment — 23 September 2026

Compared the reference store's `ingestTotals`, `currentRates` and `latencyPercentile` semantics with Graphlab's gate and interface collector. The resulting [contract](application-telemetry.md) deliberately names its measurement: receive completion to successful echo-send completion on one process monotonic clock. It excludes network transit and receive wait, requires no synchronized hosts, and reports histogram overflow honestly. Missing reports and first/restart/gapped rates remain unavailable. Reporting does not generate traffic.

SDK 1.3.0 preserves the original uninstrumented lifecycle API and gate wire version. `app-a` enables the optional v1 report; `app-b` remains uninstrumented. Status/report bounds are 4096/3072 bytes. SQLite keeps at most 1000 latest records and 10000 history reports globally, with 24-hour history retention. Queries return at most 200 reports. The authenticated API and console retain counters as decimal strings and keep application measurements separate from network-interface observations.
